### Fix: Cohere chat now uses the Compatibility API endpoint

- Chat requests to Cohere went to `https://api.cohere.ai/v1/chat/completions` and Cohere answered 405: the native API has no OpenAI-shaped route there (its Chat API is `/v1/chat` with `{message, chat_history}` in v1 and `/v2/chat` with a `messages` array in v2). The registry now points cohere at Cohere's own Compatibility API, `https://api.cohere.ai/compatibility/v1/chat/completions` (docs.cohere.com/docs/compatibility-api), which serves the OpenAI Chat Completions shape — including streaming, tools, and structured outputs — with the same Bearer key, so the generic OpenAI forward needs no translation. Upstream (luqman-v1/9router-go at 298fee33, and serenhope's cohere.js) still point at the dead `/v1` path, so this is fork-only until upstream moves.
- The sibling lanes follow from the same base URL: embeddings now resolve to `compatibility/v1/embeddings` (documented on the same page), and the models probe to `compatibility/v1/models` (verified to exist: it answers 401 without a key, same as the old `/v1/models`). Rerank is the exception — the Compatibility API has no rerank lane (OpenAI has none), so `buildRerankURL` resolves a compatibility base on the native `/v1/rerank` instead of inventing `/compatibility/v1/rerank`.
- Verified: new tests `TestCohereChatUsesCompatibilityEndpoint`, `TestHandleChatCompletions_CohereCompatibilityEndpoint` (mock upstream receives POST /compatibility/v1/chat/completions), plus compatibility cases in `TestBuildRerankURL`, `TestBuildEmbeddingsURL`, and `TestCompatibleNodeModelsURLFollowsTheChatRoute`, pass; `make build` passes (binary embeds 1.9.16-exp.10). No provider connections were checked or tested live. The endpoint probes used no key: an unauthenticated POST to the old path answers 401 (auth is checked before routing), so the 405 in Arthur's log is only visible with a valid key.
