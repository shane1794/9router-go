### Fix: Codex web-search translation no longer leaks into non-Codex requests

- `buildResponsesBody` in `internal/proxy/executor/transform.go` called `translateCodexClaudeWebSearch` and `translateCodexClaudeWebSearchChoice` unconditionally, on every Responses request that passed through it — including the Muse, opencode-zen, GitHub, Kimi, and commandcode-goat forwarders, not just Codex. Any function tool named `web_search_20250305` was silently rewritten into a hosted `web_search` tool, even when the request had nothing to do with Codex. Upstream applies the same translation only inside `shapeCodexResponsesBody`, which runs solely on the Codex forward path (`ForwardCodex`, under the Codex contract), so the fork's extra calls were pure divergence: the 4 lines were deleted, and `transform.go` now matches upstream exactly.
- The bug arrived with the 2026-11-13 merge, which dropped the fork's `applyCodexModelShape` call but left the two helper calls inline in `buildResponsesBody`. It was caught by the upstream test `TestResponsesBuilderDoesNotApplyCodexShape`, which failed on the fork since that merge (and passed on pure upstream 21d1fc5a).
- Verified: `TestResponsesBuilderDoesNotApplyCodexShape` passes; the Codex end-to-end test `TestBuildResponsesBody_CodexClaudeWebSearchEndToEnd` still passes (translation still happens for real Codex requests via `shapeCodexResponsesBody`); the `translateCodexClaudeWebSearch*` unit tests still pass; `gofmt` clean; `make build` passes (binary embeds 1.9.17-exp.4). No provider connections were checked or tested live.
