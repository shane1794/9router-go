### Fix: connections added from the media provider page keep their API key

- The Add Connection modal on the media (web search/fetch) provider page sent the pasted key as `key:`, but `POST /api/connections` only reads `apiKey` (or `data.apiKey`). The key was silently dropped at creation: the connection was stored active but key-less, so every search request went out with an empty `x-api-key` and Exa answered `{"code": "invalid_api_key", "message": "no API key found"}` even though the key itself was valid. Every other add-connection flow already sends `apiKey:`; only this page was wrong.
- The modal now sends `apiKey: newConnKey.trim()`. The backend create handler and the `CreateConnectionPayload` type are unchanged.
- Note: connections created before this fix stay key-less; re-add them from the media page, or paste the key via the Providers tab Edit modal (which has the API key field with a Check button). The media page's inline Edit modal only edits Display Name + Active.

No provider connections were checked or tested live.
